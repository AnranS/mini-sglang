## 怎么用这份指南

**跟着数据走。** 每读一个函数都问三个问题：这个张量从哪来、形状是什么、接下来谁读它。mini-sglang 的难点几乎都不在算法，而在「同一份数据被谁、在哪个 CUDA stream 上、什么时候读写」。

**先单进程，后多进程。** 阶段 1 到 7 都用 `LLM` 类在一个进程里调试，没有 ZeroMQ、没有子进程，普通断点就能用。多进程服务化放到阶段 8。

**先关 overlap，再开。** 设 `MINISGL_DISABLE_OVERLAP_SCHEDULING=1`，主循环会变成「调度 → 前向 → 处理结果」的顺序执行。看懂顺序版本，再去理解 CPU 和 GPU 错开一拍的版本。

**答完自测题、做完实验才算过关。** 每章的参考答案默认折叠。答不上来就回去读代码，别急着展开。

<Aside type="tip" title="文中的代码和行号不会过时">
  所有源码链接、代码摘录和行数都在构建时从当前提交的源码里按符号名查出来，代码一改，下一次构建就会自动更新；如果某个函数被删掉或改名，构建会直接失败，而不是留下一个错误的链接。文中的实测数字来自一台 RTX 4080 SUPER（16 GB，算力 8.9）和 Qwen3-0.6B，换一张卡会有差异。
</Aside>
